# 클러스터 메뉴 설계안 (초안)

같은 인트라넷의 여러 서버가 메인 서버의 작업을 나누어 처리한다. 첫 버전(MVP)을 구현했다: `genomecurator/cluster.py`(메인), `clusterworker.py`(워커), 화면 `/cluster`, 테스트 `tests/test_cluster.py`.

## 원칙
1. **메인이 유일한 원본이다.** DB(SQLite)와 모든 데이터의 원본은 메인에 있다. 서브는 작업용 임시 사본만 갖는다.
2. **서브가 가져간다(pull).** 서브 에이전트가 메인 API에서 작업을 받아 간다. 메인이 서브에 접속해 밀어 넣지 않는다.
3. **입력은 고정된 스냅샷이다.** 작업 명세에 입력 파일 목록과 SHA-256을 적고, 서브는 받은 뒤 해시를 확인한다.
4. **서브는 작업이 끝나 메인이 인수했다고 확인할 때까지만 데이터를 가진다.** 인수 확인(ack) 뒤 작업 폴더를 지운다.
5. **도구는 데이터가 아니다.** BEAST, IQ-TREE 등은 서브마다 설치하고 버전을 고정하며, 등록할 때 알린다.
6. **비공개 서열은 기본적으로 서브로 보내지 않는다.** 작업마다 명시적으로 허용한 경우에만 보내고, 끝나면 폴더를 지운다.
7. **앱은 Pathoplexus에 업로드하지 않는다.** 클러스터에서도 같다.

## 작업 상태
`대기 → 배정 → 입력 전송 → 실행 → 결과 전송 → 인수 확인 → 정리`
- 실패: 서브가 오류를 보고하거나 heartbeat가 끊기면 `대기`로 돌아가 다른 서브가 받는다(시도 횟수 상한, 상한 후 `오류`).
- 입력이 고정 스냅샷이라 재시도 결과는 같다. 결과는 작업 번호와 해시로 받아 중복 수신을 거른다.
- 메인이 죽으면: 실행 중인 작업은 서브가 끝까지 돌린다. 결과와 보고는 서브에 남겨 두었다가 메인이 돌아오면 보낸다. 새 작업 배정은 멈춘다.

## 서브 에이전트
- 등록: 이름, CPU 코어, 메모리, 설치된 도구와 버전, 작업 폴더의 여유 공간. 서브마다 개별 키로 인증하고 폐기할 수 있다. 키는 사용자가 직접 만들어 넣는다.
- heartbeat: 일정 간격. 일정 시간 끊기면 메인은 그 서브의 작업을 되돌린다.
- 작업 수령 조건: 필요한 도구와 버전이 있고, 코어와 메모리가 맞고, 비공개 허용 여부가 맞을 때만 가져간다.
- 서브는 DB에 직접 쓰지 않는다. 모든 보고는 메인 API를 거친다(SQLite 단일 기록자 유지).

## 메인 API (초안)
| 호출 | 용도 |
|---|---|
| POST /cluster/register | 서브 등록과 능력 보고 |
| POST /cluster/heartbeat | 생존 신호, 진행 상황 |
| POST /cluster/claim | 맞는 작업 하나 받기 |
| GET /cluster/jobs/{id}/inputs/{sha} | 입력 파일 내려받기(해시로 확인) |
| PUT /cluster/jobs/{id}/outputs/{sha} | 결과 올리기 |
| POST /cluster/jobs/{id}/done / fail | 완료, 실패 보고 |
| POST /cluster/jobs/{id}/ack | (메인→서브 응답) 인수 확인, 서브가 폴더를 지움 |

## 재현성
작업마다 `repro` 매니페스트를 붙인다(입력 해시, 서브 이름, 도구 버전, 매개변수, 결과 해시). 어느 서브에서 돌렸는지 기록되고 같은 입력이면 같은 결과임을 대조할 수 있다.

## 화면(클러스터 메뉴)
- 서브 목록: 상태(온라인/끊김), 도구와 버전, 현재 작업, 마지막 heartbeat, 여유 공간.
- 작업 큐: 상태, 배정된 서브, 진행 시간, 시도 횟수, 재시도/취소.
- 작업 만들 때: "서브에서 실행" 선택, 비공개 서열 허용 체크(기본 꺼짐), 필요한 도구.

## 나중에 (지금은 하지 않음)
- 같은 입력 반복 실행(시드)을 위한 서브의 해시 캐시.
- 메인 복구: SQLite 복제(NAS 등)와 사람이 승격하는 대기 메인. 자동 승격은 필요가 확인된 뒤에.
- 한 분석을 잘게 쪼개 나누기(처음에는 BEAST 한 번, IQ-TREE 한 번 같은 기존 실행 단위를 한 작업으로).

## 첫 구현 범위 (MVP)
서브 등록과 heartbeat, 작업 수령, BEAST 작업 하나를 서브에서 실행하고 결과를 해시로 확인해 인수하는 흐름, 서브 끊김 시 재배정, 클러스터 화면의 서브 목록과 작업 큐.

## 사용법 (구현된 첫 버전)
1. 메인을 다른 서버가 접속할 수 있게 띄운다: `genomecurator serve --host 0.0.0.0`. 워커 등록과 작업 추가는 메인이 있는 컴퓨터에서만 된다(`GC_CLUSTER_ADMIN_REMOTE=1`이면 다른 컴퓨터에서도 허용). 같은 인트라넷 안에서만 쓰고 바깥에 열지 않는다.
2. **시스템 > 클러스터**에서 워커를 추가한다. 키는 그때 한 번만 보인다.
3. 워커 서버에서: `genomecurator worker --main http://메인:8000 --key <키> --workdir gc-worker` (BEAST가 설치되어 있어야 한다. 위치는 `--beast`로 지정할 수 있다).
4. 준비된 BEAST 폴더를 작업으로 넣는다(화면 또는 `genomecurator cluster-submit <폴더>`). 결과는 같은 폴더에 들어오고 `cluster_job.json`에 어느 워커가 돌렸는지와 파일 해시가 남는다.

## 알려진 한계 (첫 버전)
- 작업 종류는 BEAST 하나, 워커당 한 번에 한 작업. 입력 캐시와 대기 메인 복구(SQLite 복제)는 아직 없다.
- 워커와 메인의 통신은 암호화하지 않는다(HTTP). 키는 요청 머리글로 오간다. 신뢰하는 내부망에서만 쓴다.
